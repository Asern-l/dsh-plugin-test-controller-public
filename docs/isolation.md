# 隔离与恢复边界

## 本项目保证的范围

在受信任插件遵守目录约定、运行器能够完成清理的前提下，每轮测试使用独立的：

- `DSH_HOME`：配置、profile、会话及 DSH 自身状态。
- `DSH_AGENTS_HOME`：共享 Agent 配置根。
- `HOME` / `USERPROFILE`、AppData、XDG 配置/缓存/数据目录。
- 工作区与 TEMP / TMP / TMPDIR。
- 新启动的 DSH 进程，不恢复旧 Session ID。

只继承基础进程启动变量和操作者在计划中显式允许的变量。`NODE_OPTIONS`、日常 DSH 配置、GitHub token、旧模型凭据等不会隐式继承。

headless 配置关闭 DeepSeek 会话日志贡献及 OTel 会话上传、自动调用模型生成标题，并关闭宿主机说明文件和文件系统 skill 的自动发现，避免从工作区祖先或共享目录吸收旧上下文。待测插件仍可以自行注入明确的测试上下文。

每轮会保留管理记录与显式导出的证据。这些文件不会自动输入新会话；具备宿主机任意读权限的受信任插件仍可能主动读取它们。

## 进程终止

- Windows：独立 PowerShell 宿主进入启用 `KILL_ON_JOB_CLOSE` 的 Job Object，然后启动 DSH。宿主退出时，剩余成员被系统终止；取消和超时还会中止该进程树。普通继承的后代进程包含在内。
- Linux：DSH 使用独立进程组；正常退出、取消、超时和输出超限都会清理该组。主动创建新 session 逃离进程组的插件不在此保证内。
- 控制插件卸载：取消由该次插件实例启动的任务，后台运行器继续执行清理。
- 管理用 DSH 崩溃：独立运行器继续运行到完成或超时。
- 运行器被强制杀死、机器掉电：可能留下本地目录；用 `recover` 在核对进程状态后恢复。Linux 上可能还需要人工停止残留进程。任何清理失败都会在状态中保留，不会冒充干净完成。

## 不属于本项目保证的范围

- 插件在宿主机其他目录写文件、改注册表、安装全局依赖或操作外部数据库。
- 模型服务端的日志、保留策略、缓存和模型本身的知识。
- 目标真机上的系统配置、服务、内核模块、微码、频率设置和微架构状态。
- 主动逃离进程约束的代码、恶意插件、同用户其他进程篡改运行目录。
- 模型响应逐字一致或硬件测量逐次一致。

需要整个操作系统恢复到安装前状态时，应在临时虚拟机或快照中运行本项目。涉及微架构实验时，仍需在目标真机上记录和控制真实硬件条件。

## 文件删除规则

运行根目录必须为空目录或具有本项目所有权标记。清理只删除经过 run ID、目录边界、sandbox 标记和符号链接检查的 sandbox 子目录。嵌套链接被删除时不追随目标。归档与其他目录不会被清理操作递归删除。

这些检查用于防止正常操作中的误删，不把同用户可任意改写的目录当成安全边界。
